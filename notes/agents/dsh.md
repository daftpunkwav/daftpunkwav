# dsh（DeepSeek Harness）

> DeepSeek · 桌面应用 + 本地 Web GUI 的 Agent harness · 开源（MIT）

## 是什么

一个跑在本地的 Agent harness。形态上不是「一个 CLI」，而是桌面应用里带一个本地 Web GUI（默认监听 127.0.0.1 的端口），对话、工具调用、后台任务、子代理、文件卡片都在这个界面里。

官方对它的定位是「Everything is a Plugin」——万物皆插件，桌面本身也是插件。

## 技术形态

- **工具是一等公民**：文件读写与编辑、glob/grep 检索、终端执行、网页检索与抓取、提醒调度、文件卡片投送，都是内置工具，不需要自己搭壳。
- **后台任务**：耗时的命令会自动转成后台 job，对话不会卡住，job 可以随时回来看输出、也可以杀掉。
- **子代理与工作流**：可以把一段自包含的任务派给独立上下文的子代理；也可以用脚本编排多个子代理分阶段并行，把结果按结构化 schema 收回来。
- **技能包（Skills）**：可复用的任务说明 + 脚本，按需加载进上下文，属于「提示词即代码」的做法。
- **文件沙箱分三档**：只读、工作区可写、全权限。策略明确写在提示里，越权操作会被直接拒绝而不是静默放行。
- **计划 / 目标模式**：复杂任务先出计划再执行，长任务可以挂成带轮次上限的持续目标。
- **插件生态已经跑起来了**：官方仓库之外，社区有插件精选、桌面发行版、可视化插件市场等一整套外围项目——这说明「万物皆插件」不是口号，是真的有人靠它扩展。

## 我的使用结论

**适合**：需要「一个界面统管多件事」的场景——一边跟 Agent 对话，一边看它跑后台任务、审它交上来的文件、决定要不要派新活儿出去。它也是我写自己项目时最顺手的实验台，因为工具边界清晰、子代理不会污染主上下文。

**不适合**：想要一个极简、可以塞进 CI 或脚本里的 Agent——它太重了，不是为无头运行设计的；另外对纯终端党的我来说，开 GUI 这一步本身是成本。

**和其他工具比**：和 Claude Code / Codex CLI 的差别是「谁当界面」：CLI 工具把界面交给终端，dsh 把界面做成了应用，并且把后台任务、子代理、工作流这些编排能力做进了产品形态。它更接近一个可以长期停驻的开发工作台，而不是一次性的命令行调用。
