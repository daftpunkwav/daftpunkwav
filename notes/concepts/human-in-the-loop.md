# 人工确认

> 高风险动作的决策权，交回给人。

## 判断

Agent 的自主性不是越高越好。自主性应该和动作的可逆性挂钩：

- **可逆、低影响**（读文件、跑测试、格式化）：放手让它做。
- **不可逆或对外可见**（发消息、付款、删数据、提交代码、部署）：先问人。

人工确认的关键不在于弹个窗，而在于**确认的对象**：应该展示「将要发生什么」，而不是「要不要继续」。

## 三个必须想清楚的点

1. **拦截点在哪一层**：放在工具层最稳（所有工具调用都要过），放在提示词层最弱（模型可能绕过自己写的约束）。
2. **确认信息够不够**：人只有 1～2 秒扫一眼。要给出动作、目标、影响范围，以及「会发生什么」的直白描述。
3. **超时怎么办**：没人确认时默认放行还是默认拦截？涉及钱和数据删除的应该默认拦截。

## 常见坑

- **粒度太粗**：把一长串操作打包成一次确认，人只能整体点头，等于没审。
- **弹窗疲劳**：每步都问，人会开始闭眼点「同意」。把可以自动完成的先自动完成，只对真正不可逆的点问。
- **默认放行**：把「超时未确认」当成同意，风险动作就等于没有拦截。
- **只在 UI 上拦截**：CLI 或脚本路径绕过 UI 拿不到确认。拦截要在服务端/工具层，而不是某个前端。
