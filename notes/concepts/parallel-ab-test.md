# 并行对照实验

> 想知道哪种方案更好，就让它们同时跑同一道题。

## 判断

Agent 生态里最贵的误会是凭感觉选框架。谁的 demo 更炫、谁的介绍更顺，往往和实际效果没关系。

对照实验的价值在于**把变量固定住**：同一道题、同一批工具、同一套预算、同一时间窗，然后并排看结果。看起来笨，但它把感觉换成了可比较的数据。

Agent 的输出有随机性，所以对照实验有三个必须处理的细节：

- **题目要有判据**：开放式题只能看主观评分，容易变成我觉得这个好。有可自动校验的判据（能不能编译、跑不跑得过测试）时，结论才硬。
- **一次只动一个变量**：同时换模型和换提示词，出了差异也不知道是谁的功劳。
- **过程也要看**：只看最终答案会丢掉大量信息。中间步骤、工具调用次数、耗时、token 消耗，往往比答案更能解释差异。

## 并行带来的额外价值

并行跑还有个副作用好处：**同一道题上的分歧，本身就是信息**。几种方案答案一致，说明题目简单或者大家都在犯同样的错；答案差异大，说明这道题确实在区分能力。

## 常见坑

- **题目太少**：三道题得出的结论没有统计意义。
- **只看一个指标**：只比正确率会掩盖成本和延迟；只比速度会掩盖质量。
- **不记录原始输出**：只有分数没有原始轨迹，过半年无法复盘。
- **并行度开太高**：同时发起十几个 Agent 会互相抢 API 配额，反而更慢。要留出每个方案的独立预算。

## 落到我自己的项目
