# 断点续跑

> 状态外置，而不是指望模型记住。

## 判断

长任务 Agent 一定会被打断：上下文超限、模型报错、机器重启、用户切走。能不能接着跑，决定了它是一次性 demo 还是能真用的工具。

关键不在于把 prompt 存下来，而在于把**进度**变成可外部校验的状态：

- **任务被拆成可独立验证的步骤**，每步都有明确的完成判据。
- **判据来自工作区的真实状态**（文件、测试、构建产物），而不是模型自己说完成了。
- **中断时可以重建上下文**：读回状态、跳过已完成的步骤、继续下一步。

## 为什么不让模型自己报进度

模型自述完成度是不可靠的：它会描述一个本该存在的文件，会把打算做的事说成已经做完。一旦把模型自述当成状态，续跑就会在错误的前提上继续，错误被放大。

所以在评测任务里，我把完成判据落在工作区断言上：模型负责提议怎么改，断言负责说改没改成。

## 常见坑

- **步骤粒度太粗**：一个步骤跑三十分钟，中断一次就全丢。粒度应该细到几分钟能重做一遍。
- **状态只存在内存**：进程一挂全没。状态要落盘。
- **续跑时重新喂全部历史**：上下文越滚越大。应该只喂还差什么。
- **判据可被绕过**：如果测试本身是模型写的，它可能写成永远通过的样子。判据要尽量由外部约束（类型检查、lint、既有测试）提供。
